# Intent

Фабричное ядро написано (US1–US6, durable-раннер ADR-024/025), но **MVP нельзя принять**: оператор не может вести продукт и изменение из интерфейса. Узла «Продукт» в домене нет (только `RepositoryRef` внутри изменения), фабрика не готовит репозиторий (клона нет — воркспейсы минтятся из операторских зеркал), диалога по спеке нет (агент умеет только остановиться), поверхностей просмотра и правки артефактов нет, непонятен следующий шаг (CLI низкоуровневый), а консоль — 6 экранов наблюдателя.

Подтверждение: весь журнал живого пилота T043 — это оператор, вручную делающий работу консоли (approve в скрипте, ручной merge спек-CR, ручной merge-forward, прикрепление контракта через `--contract-json`).

Цель: оператор ведёт изменение от идеи до работающего приложения **из Console или CLI**, без низкоуровневых команд и ручных правок артефактов агента, и на каждом шаге видит ровно один следующий шаг.

Видение оператора (17 шагов, 8 фаз Ф0–Ф8) и ответы на 11 уточняющих вопросов зафиксированы в плане `docs/plan-changeset-workspace-mvp.md`; архитектурные решения — ADR-030…ADR-037; декомпозиция работ — `specs/001-dark-factory-mvp/tasks.md` (Phase 11, T062–T118).

Этот ChangeSet переводит ту работу в каноническую форму Native SDD Core (ADR-020): дельта требований, дизайн, задачи, план проверок, обязательство reconciliation по риск-классу R2.
