# ADR-011: Risk-Based Merge and Release Policy

- **Статус**: принято
- **Дата**: 2026-09-13
- **Автор**: software-architect
- Решение согласовано пользователем (ответы на вопросы раздела 5 plan.md, 2026-09-13)
- Уточнено по ревью пользователя (2026-09-13): политика ограничена merge/release; модель участия человека по фазам создания решения вынесена в [ADR-018](ADR-018-human-participation-autonomous-execution.md). Прежнее название — «Human Off The Loop Release Policy».
- **Уточнено** (2026-09-13, архитектурное ревью ADR-пакета): авторизация GitOps-MR через trusted finalizer (п.2)

## Контекст

- Q-10 plan §5: «merge — только человек, production вне MVP» (авто только «после формальных gates и накопления статистики») против «Human Off The Loop с автоматическим релизом низкого риска».
- Ревью ADR (2026-09-13) выявило смешение двух независимых политик: участие человека в merge/deployment (этот ADR) и участие человека в создании решения по фазам (требования, UX/UI, архитектура — [ADR-018](ADR-018-human-participation-autonomous-execution.md)). Прежнее название создавало впечатление, что вся фабрика работает без человека; кроме того, формулировка «цикл не блокируется человеком» противоречила правилу «merge в MVP — только человек».
- Влияние: merge policy (T-032), скорость цикла, требования к статистике перед авто-merge (T-085), риск-уставка R-классов.

## Решение

1. Политика разделяет discovery/design, autonomous implementation и release authorization. Этот ADR регулирует **release authorization** — merge и развёртывание; discovery/design и autonomous implementation (Implementation Contract, условия эскалации, границы автономии) — [ADR-018](ADR-018-human-participation-autonomous-execution.md).
2. В MVP merge — только человек: protected branch, обязательные approvals, гейты (T-032). Низкорисковое изменение (R0/R1) **автономно доводится до готового к merge состояния** (MR с release evidence); **после ручного merge развёртывание в dev выполняется автоматически** (GitOps, ADR-010). Автоматический dev-deploy выполняет **trusted finalizer**: он создаёт GitOps-MR с immutable digest и merge'ит его после фиксации ручного merge продуктового MR, зелёных гейтов и валидного release evidence; у agent pods таких credentials нет (T-032, T-044); второй human approval на GitOps-MR не требуется — авторизация deploy'а остаётся у человека, утвердившего merge; `dark-factory-gitops` защищён отдельно (CODEOWNERS, запрет прямых push, ADR-015). До T-085 это не полный Human Off The Loop, а **autonomous implementation with human release gate**.
3. **Auto-merge для R0/R1 — policy-controlled, отдельная задача T-085** после накопления статистики пилота (T-072): при выполнении формальных условий merge выполняется автоматически — только тогда цикл R0/R1 на непрод-контуре становится полным Human Off The Loop. Включение/отключение — переключателем с audit-log.
4. В MVP один контур (dev): «test stage» целевой модели в MVP = dev-контур; отдельные stage/prod окружения и автоматизация prod — пост-MVP (T-091). Релиз в **Prod — только вручную после валидации** (smoke/evidence), до отдельного ADR.
5. Вход политики — риск-классы R0–R4 (T-080): LLM может повысить класс, понизить — только формальная политика.
6. Автоматическое развёртывание опирается на release evidence (digest, Argo status, smoke — T-045); неуспешный smoke не переводит изменение в Released и служит сигналом отката (revert GitOps-коммита, ADR-010).

Связанные задачи: T-032, T-045, T-080, T-085. Модель участия человека по фазам: [ADR-018](ADR-018-human-participation-autonomous-execution.md).

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Merge — только человек, production вне MVP | Максимальный контроль | Не проверяет целевую модель автономии; медленный цикл даже при низком риске | Отклонено как политика (остаётся MVP-механикой merge до T-085) |
| Human Off The Loop с автоматическим релизом низкого риска | Скорость цикла; проверка автономии на непрод-контуре | Требует риск-классов, evidence и статистики; prod автоматизировать на старте рано | Выбрано как целевая модель, с ограничениями: в MVP — human release gate; авторелиз — в непрод; Prod — ручной |
| Один ADR, совмещающий участие человека и release policy (прежняя редакция ADR-011) | Один документ | Смешивает release policy с операционной моделью фабрики; название вводит в заблуждение | Отклонено: разделено на этот ADR (merge/release) и [ADR-018](ADR-018-human-participation-autonomous-execution.md) (участие человека по фазам) |

## Последствия

**Позитивные**
- Низкорисковое изменение автономно доводится до готового к merge состояния; после ручного merge его развёртывание в dev выполняется автоматически. Устранено противоречие прежней редакции («цикл не блокируется человеком» vs «merge — только человек»).
- Статистика для T-085 собирается легально с первого пилота.

**Негативные / риски**
- Ошибка риск-классификации «понижает» опасное изменение — митигируется запретом LLM-понижения класса (T-080).
- Авторелиз без человека требует безусловного smoke/evidence и отработанного revert-пути (T-045, T-043).
- До T-085 merge остаётся ручным — осознанное ограничение скорости цикла для MVP.
