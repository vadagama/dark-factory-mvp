# ADR-002: Python Core Stack for Factory Core

- **Статус**: принято
- **Дата**: 2026-09-13
- **Автор**: software-architect
- Решение согласовано пользователем (ответы на вопросы раздела 5 plan.md, 2026-09-13)
- **Уточнено** (2026-09-13, архитектурное ревью ADR-пакета): стоимость будущей миграции на Temporal описана реалистично (п.7, синхронизировано с ADR-003)

## Контекст

- Q-1 plan §5: язык/стек Factory Core — «Go + Temporal-воркеры» против «Python модульный монолит (PydanticAI/pydantic-graph)».
- Влияние: весь код конвейера, найм/навыки, скорость итераций; блокер для T-002 (scaffolding).

## Решение

1. Factory Core — **Python**, модульный монолит (границы модулей — HLD §4; репозитории — ADR-015).
2. Агентный harness — **PydanticAI** за `HarnessPort` (T-010); смена исполнителя — второй адаптер того же порта (T-089).
3. **pydantic-graph** — только внутри стадии (ADR-005); межстадийный Flow — собственный лёгкий workflow-core.
4. API — **FastAPI** (`api`), CLI-entrypoint исполняется в CI job или локально; Console — React (ADR-014).
5. Pydantic v2 — язык контрактов доменной модели (T-003); инструменты качества: ruff, mypy (strict на core), pytest.
6. LLM endpoint — существующий LiteLLM; конкретные модели не зашиваются в код.
7. «Лёгкое подключение Temporal позже» (Q-1/Q-2) — через сохранение границы `WorkflowEnginePort` (ADR-006): стадии и агенты не знают движок. Позже — адаптер Temporal поверх того же порта (ADR-003); это не бесшовная замена адаптера: потребуется отображение модели состояния, миграция активных executions и повторная валидация идемпотентности.

Связанные задачи: T-002, T-010, T-011, T-089.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Go + Temporal-воркеры | Производительность, статическая типизация, зрелый durable engine | Второй стек параллельно с агентами/packs (Python), медленнее итерация промптов/контрактов, Temporal-инфраструктура в MVP | Отклонён: выбран Python-стек; Temporal решён отдельно (ADR-003) |
| Python модульный монолит (PydanticAI/pydantic-graph) | Один стек с агентами и packs, быстрый цикл, нативные PydanticAI/pydantic-graph | Дисциплина границ модулей; чистая CPU-производительность не целевая | Выбрано |

## Последствия

**Позитивные**
- Один релиз и lockfile для CLI, API и контрактов; Pydantic-модели переиспользуются от домена до OpenAPI.
- Быстрая итерация промптов/skills — основная стоимость фабрики.

**Негативные / риски**
- Требуется жёсткая mypy-политика и проверка границ импортов в CI, иначе монолит расползается (T-002).
- Не выбирать библиотеки с тяжёлыми нативными зависимостями (ARM64-контур, ADR-010).
