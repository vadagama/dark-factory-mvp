# Правила пака `ui` (Small UIKit)

Правила обязательны для кита и для продуктов-потребителей `@small/ui`.
На контракт детерминизма ссылается `playwright.config.ts`
(`packs/ui/blueprint/ui/`); несоблюдение любого пункта ловится гейтами или
ревью (ADR-014 п.3).

## Контракт детерминизма visual regression

Visual-гейт (`tests/visual/uikit.spec.ts` + `playwright.config.ts`) сравнивает
каждую историю Storybook с коммиченным бейзлайном. Он имеет смысл только при
жёсткой детерминизации окружения:

- **Закреплённый браузерный образ.** CI-джоба visual-гейта выполняется в
  контейнере `mcr.microsoft.com/playwright` с тегом, равным версии
  `@playwright/test` из `package-lock.json` (сейчас `v1.63.0-noble`; в фабричном
  CI тег дополнительно пиннится дайджестом). Локальная регенерация бейзлайнов
  допустима только в том же контейнере — иначе пиксельные расхождения OS-
  шрифтов и рендера будут неотличимы от реальной деградации.
- **Фиксированные параметры рендера** (`playwright.config.ts`, блок `use`):
  viewport 1280×720, `deviceScaleFactor: 1`, `locale: en-US`, `timezoneId: UTC`,
  `colorScheme: light`, `reducedMotion: reduce`. Браузер — только chromium
  (проект `chromium`).
- **Анимации отключены** в снимках: `expect.toHaveScreenshot.animations =
  "disabled"` (и в конфиге, и в самом тесте) — анимации Radix не создают
  нестабильных кадров.
- **Порог расхождения:** `maxDiffPixelRatio 0.01` — допуск на осознанный
  рендер-джиттер; всё сверх него — провал истории. Порог меняется только через
  ревью с объяснением.
- **Бейзлайны коммятся** рядом со спекой
  (`tests/visual/uikit.spec.ts-snapshots/`, без платформенного суффикса —
  браузер закреплён) и обновляются **только через ревью**: регенерация в
  закреплённом контейнере
  (`npm run test:visual -- --update-snapshots`), дифф бейзлайнов инспектируется
  в MR как визуальное изменение спеки. Бейзлайн — часть спеки: его «улучшение»
  без ревью приравнивается к обходу гейта.

## Дисциплина токенов

- Источник токенов — `tokens/*.tokens.json` (DTCG). `src/tokens.css` и
  `src/tokens.ts` — генерат `scripts/build-tokens.mjs` (`npm run tokens:build`),
  руками не редактируется; дрейф генерата против источника ловит vitest
  drift-тест (`tests/tokens.test.ts`).
- В рукописном CSS кита и продуктов цвета задаются только через
  `var(--small-*)` (или `currentColor`/`transparent` там, где это
  семантически оправдано); hex- и именованные цвета блокирует stylelint
  (`stylelint.config.js`). Единственное исключение — сгенерированный
  `src/tokens.css`: единственное место «сырых» значений, под drift-тестом.
- Radix-примитивы (`@radix-ui/*`) — деталь реализации кита: прямые импорты
  допустимы только в `src/components/**` кита и запрещены в продуктовом коде.

## Публичная поверхность

- Продукт импортирует кит только из корня пакета:
  `import { Button } from "@small/ui"` (+ отдельные side-effect импорты
  `@small/ui/tokens.css` и `@small/ui/styles.css`). Deep-импорты
  `@small/ui/...` запрещены: всё вне `src/index.ts` не покрыто гейтами и
  visual-бейзлайнами кита.
- Правило исполняет ESLint-политика `policy/eslint-small-ui.mjs`: она
  подключается в flat-config продуктового репозитория и проверяется самотестом
  гейтов (`npm run test:gates` линтит `policy/fixtures/` именно этим файлом —
  нарушения блокируются, чистый импорт проходит).
- Сам кит импортирует себя только относительными путями (`eslint.config.js`),
  экспортирует всё через `src/index.ts`.

## WCAG 2.2 AA acceptance checklist

Автоматизируемую часть (axe- violations, программный контраст базовых
состояний) покрывают тесты кита. Следующие критерии автоматизация не
закрывает — **каждый подтверждается человеком при приёмке UI-паттерна** и
фиксируется как UI evidence (ADR-014 п.3, ADR-018 п.1):

- [ ] **Контраст нестандартных состояний** — hover/active/focus/disabled/
      placeholder и комбинации тонов читаемы на реальном фоне, включая
      состояния, которые не попадают в программный контраст-тест.
- [ ] **Фокус-порядок в живом приложении** — порядок Tab/Shift+Tab логичен на
      реальной странице (не только в jsdom), видимый focus-ring не теряется на
      фоне, в диалогах фокус-ловушка и возврат фокуса работают руками.
- [ ] **Скринридер-сценарии** — имена и роли объявляются корректно (VoiceOver/
      NVDA): диалоги, вкладки, select, поля с ошибками; текст ошибки связан с
      полем и озвучивается.
- [ ] **Понятность текстов ошибок** — сообщения об ошибках и подсказки
      сформулированы так, что пользователь понимает, что произошло и что
      делать (критерий 3.3.1/3.3.3 — «понятность» не автоматизируется).

Чеклист заполняется при появлении нового паттерна или изменении токенов/
состояний компонентов; результат прикладывается к ChangeSet как UI evidence.
