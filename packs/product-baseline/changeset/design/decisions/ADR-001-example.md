## Контекст

Пример (иллюстративный). Требование `req:example-product:checkout:timeout`:
оформление заказа, не завершившееся за отведённое время, прерывается с явной
ошибкой; длительность таймаута меняется без изменения кода.

## Решение

Длительность таймаута читается сервисом заказов из конфигурации при старте
(ключ `checkout.timeout`), а ошибка таймаута возвращается клиенту как отдельный
код ответа, который экран подтверждения показывает пользователю.

## Обоснование

Конфигурация — единственный источник значения: смена таймаута не требует релиза
кода, а отдельный код ошибки позволяет экрану отличить таймаут от прочих отказов.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Константа в коде | Просто | Смена значения требует релиза | Противоречит требованию AC-2 |
| Таймаут на стороне клиента | Не трогает сервис | Сервис продолжает обработку после отмены клиентом | Не прерывает оформление на сервере |

## Последствия

- Сервис заказов получает новый параметр конфигурации; значение по умолчанию
  фиксируется в конфигурации окружений.
- Публичный API получает код ошибки таймаута; экран подтверждения показывает
  состояние ошибки (`SCR-001`).
